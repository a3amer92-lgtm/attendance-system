نظام الحضور والانصراف (شاشة واحدة فقط)
=======================================
المتطلبات: Node.js 18 أو أحدث. لا يحتاج npm install (بدون مكتبات خارجية).

التشغيل:
  node server.js
ثم افتح:  http://localhost:3000

تجربة المستخدمين (مفيش شاشة تسجيل دخول، المستخدم بيتحدد من الرابط):
  http://localhost:3000/?user=EMP-001   (الافتراضي)
  http://localhost:3000/?user=EMP-004
  كل المستخدمين لهم نفس الصلاحيات الكاملة (مفيش تفرقة بين موظف وHR).

⚙️ الإعدادات (متاحة لكل المستخدمين، أسفل الشاشة):
  جدول بالشيفت المطبق على كل موظف (بدون نموذج تعديل الشيفت — الشيفت لسه بيتعدل عبر الـ API: PUT /api/shifts/:id).
  🗑️ مسح الشيفت: زر لكل موظف في الجدول، وزر لمسح الشيفت المطبق على كل الموظفين.
  ➕ إضافة موظف: في الإعدادات (الاسم إجباري، القسم والوظيفة اختياريين). الموظف الجديد بيفتح من ?user=EMP-0XX وملوش شيفت.
     لو مفيش موظفين خالص، الصفحة بتعرض شاشة لإضافة أول موظف.
  🗑️ مسح كل الموظفين المسجلين: بيطلب كتابة "مسح الكل" للتأكيد، وبيعمل نسخة احتياطية مستقلة. بعده التطبيق مش هيشتغل (مفيش إضافة موظفين)؛
     للتراجع: أوقف الخادم، انسخ ملف النسخة فوق data/db.json، وشغّل الخادم تاني.
  🗑️ مسح سجلات الحضور والانصراف لكل الموظفين المسجلين (قائمة الموظفين نفسها بتفضل).
  الموظف اللي مفيش له شيفت: بيتعرض "لا يوجد شيفت"، ومبيتحسبش عليه تأخير، وأيام العمل الافتراضية أحد–خميس.
  قبل أي مسح بيتعمل نسخة احتياطية data/db.json.bak (بتتبدل مع كل مسح جديد).
  كل موظف له شيفت مستقل. الشيفتات القديمة اللي مفيهاش days بتتعامل كأحد–خميس (الجمعة والسبت عطلة) زي الأول.
  أيام العمل بتأثر على: حالة اليوم (عطلة)، ملخص الشهر، وتسجيل الحضور (بيتمنع في أيام العطلة الخاصة بالموظف).
  ملحوظة: تعديل الشيفت بيتطبق على عرض السجل بالكامل (حساب التأخير/العطلات بيتم بالشيفت الحالي).

الهيكل:
  server.js         الخادم + الـ API
  public/index.html الشاشة (نفس التصميم، البيانات من الخادم)
  data/db.json      قاعدة البيانات (25 موظف، من 1/7 إلى 29/9/2026)

الـ API:
  GET  /api/bootstrap               بيانات المستخدم والشيفت والعطلات
  GET  /api/attendance?months=YYYY-MM[,YYYY-MM]&employee_id=
  POST /api/attendance/check-in     تسجيل الحضور (بوقت الخادم)
  POST /api/attendance/check-out    تسجيل الانصراف
  GET  /api/settings/shifts         شيفتات كل الموظفين
  PUT  /api/shifts/:id              حفظ/تعديل شيفت موظف — {start,end,grace,days}
  DELETE /api/shifts/:id            مسح الشيفت المطبق على موظف
  DELETE /api/settings/shifts       مسح الشيفت المطبق على كل الموظفين
  DELETE /api/settings/attendance   مسح سجلات الحضور لكل الموظفين
  POST /api/settings/employees      إضافة موظف — {name, dept?, job?} والرقم الوظيفي EMP-### بيتولّد تلقائي
  GET  /api/setup                   عدد الموظفين (من غير هوية) — لشاشة إضافة أول موظف
  DELETE /api/settings/employees    مسح كل الموظفين (مع شيفتاتهم وسجلاتهم) + نسخة احتياطية data/db.employees-backup-<وقت>.json
                                    days = أيام العمل (0=الأحد … 6=السبت)، اختياري (لو مش مبعوت بتفضل زي ما هي)

إعدادات اختيارية (متغيرات بيئة): PORT و HOST و TZ_NAME (الافتراضي Africa/Cairo)

ملاحظات مهمة:
- الخادم بيشتغل على 127.0.0.1 فقط، لأن الهوية بتتحدد من الرابط بدون كلمة سر.
  دلوقتي أي مستخدم يقدر يمسح كل البيانات، فمينفعش تنشره على شبكة أو إنترنت من غير تسجيل دخول وصلاحيات.
- وقت الحضور والانصراف بياخده الخادم (توقيت القاهرة) مش جهاز الموظف.
- لإعادة البيانات للوضع الأصلي استبدل data/db.json بنسخة من الـ zip.
