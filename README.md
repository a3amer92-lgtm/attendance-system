# نظام الحضور والانصراف

شاشة حضور وانصراف بسيطة — تعمل بنسختين:
- **نسخة Node.js:** خادم كامل مع قاعدة بيانات (للعمل المشترك بين أجهزة).
- **نسخة GitHub Pages:** تطبيق Static يعمل بالكامل من المتصفح (للاستخدام الشخصي/التجربة).

## التشغيل محليًا
```bash
node server.js
# افتح http://localhost:3000
```
أول تشغيل بيعمل `data/db.json` فاضي تلقائيًا، وبتضيف أول موظف من الشاشة.

## تسجيل الدخول وكلمات السر
- الدخول بالرقم الوظيفي (`EMP-001` أو `1` بس) + كلمة السر. الجلسة كوكي `HttpOnly` لمدة 30 يوم.
- أول تشغيل على بيانات فاضية: صفحة الدخول بتعرض «إنشاء أول حساب».
- كلمات السر متخزنة مشفرة (scrypt) ومفيش أي API بيرجّعها.
- **تغيير كلمة السر:** الإعدادات ← 👤 حسابي. بعد التغيير أي جلسات تانية للحساب بتتقفل.
- **نسيت كلمة السر:** من الإعدادات ← جدول الموظفين ← عمود «كلمة السر» ← تعيين. (متاح لأي مستخدم زي باقي الإعدادات.)
- **حسابات قديمة من غير كلمة سر:** كلمة السر المبدئية = الرقم الوظيفي (مثلًا `EMP-001`) — غيّرها فورًا.
- 5 محاولات دخول فاشلة = قفل دقيقة.
- ⚠️ كل المستخدمين لسه بنفس الصلاحيات (بما فيها مسح كل البيانات). للنشر العام الأفضل تفرّق بين موظف ومسؤول.

## التشغيل من رابط (الاستضافة)
GitHub Pages مبتشغلش Node.js، فالمشروع بيتنشر على خدمة استضافة بتقرأ من مستودع جيت هاب:

### Render (الأسهل — فيه `render.yaml` جاهز)
1. من render.com: **New → Blueprint** واختار المستودع.
2. بعد النشر هتاخد رابط `https://attendance-system-xxxx.onrender.com`.

الملف بيطلب قرص دائم (`/data`) عشان البيانات ماتضيعش مع كل إعادة تشغيل، وده محتاج خطة مدفوعة (starter). على الخطة المجانية البيانات بتتمسح.

### Railway / Fly.io / Koyeb
فيه `Dockerfile` جاهز. اضبط المتغيرات وأربط Volume على `/data`.

### GitHub Codespaces (للتجربة فقط)
افتح المستودع في Codespaces، شغّل `node server.js` وافتح الـ port 3000 من تبويب Ports.

## متغيرات البيئة
| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `3000` | المنفذ (الاستضافة بتحدده) |
| `HOST` | `127.0.0.1` | على الاستضافة `0.0.0.0` (مضبوطة في Dockerfile) |
| `DATA_DIR` | `./data` | مكان `db.json` — اربطه بقرص دائم |
| `TZ_NAME` | `Africa/Cairo` | توقيت تسجيل الحضور |

`GET /healthz` بدون تسجيل دخول، للفحص الصحي من الاستضافة.
باقي التفاصيل (الـ API والإعدادات) في `README.txt`.

## 🌐 نسخة GitHub Pages (Static)

نسخة تعمل بالكامل من المتصفح بدون أي خادم. الملفات موجودة في مجلد `docs/`.

### الرابط المتوقع
```
https://a3amer92-lgtm.github.io/attendance-system/
```

### تفعيل GitHub Pages
1. ارفع المشروع إلى GitHub (اتبع خطوات "الرفع على GitHub" أعلاه).
2. في المستودع على GitHub: **Settings → Pages**.
3. تحت **Source** اختر: **Deploy from a branch**.
4. اختر Branch: `main` و Folder: `/docs`.
5. اضغط **Save**.
6. انتظر دقيقة أو اثنين ثم افتح الرابط أعلاه.

### التشغيل محليًا (بدون Node.js)
```bash
# أي HTTP server بسيط يكفي
cd docs
python -m http.server 8080
# أو
npx serve docs
# ثم افتح http://localhost:8080
```
> **ملاحظة:** فتح `docs/index.html` مباشرة من `file://` قد لا يعمل بسبب قيود CORS على `fetch`. استخدم HTTP server محلي.

### تخزين البيانات
- البيانات مخزنة في **localStorage** في المتصفح.
- ⚠️ **البيانات ليست مشتركة بين الأجهزة أو المتصفحات** — كل متصفح له بياناته المستقلة.
- مسح بيانات المتصفح (Clear Data) يمسح كل البيانات.
- عند أول تشغيل، يتم تحميل بيانات أولية من `data/seed.json`.

### الأمان
- كلمات السر مشفرة بـ SHA-256 مع salt عبر Web Crypto API.
- ⚠️ **هذه ليست حماية حقيقية** — البيانات مخزنة في localStorage ويمكن لأي شخص لديه وصول للمتصفح قراءتها من DevTools.
- للأمان الحقيقي، استخدم نسخة Node.js مع Backend كامل.

### الفرق بين النسختين
| الميزة | Node.js | GitHub Pages |
|---|---|---|
| التخزين | ملف `db.json` على الخادم | localStorage في المتصفح |
| مشاركة البيانات | ✅ بين كل الأجهزة | ❌ كل متصفح مستقل |
| الأمان | scrypt + HttpOnly cookies | SHA-256 + sessionStorage |
| يحتاج خادم | ✅ Node.js | ❌ ملفات ثابتة فقط |
| التوقيت | توقيت الخادم (مرجعي) | توقيت القاهرة عبر Intl API |

